# infra

The AWS resources of the opisuomea.org recruiter chatbot, defined in code with the
**AWS CDK** (TypeScript). The CDK turns this code into a CloudFormation template, and
CloudFormation creates or updates the resources to match it.

| Stack | Defined in | Contains |
|---|---|---|
| `FinAppProfileMcp` | `lib/profile-mcp-stack.ts` | The MCP server's Lambda function, its function URL (`AWS_IAM` auth), its log group (14 days), and permission for the backend's EC2 role `fin-app-ec2-bedrock` to call the URL |

`bin/fin-app-infra.ts` creates the stacks; `cdk.json` tells the CDK CLI how to run it and holds the CDK
feature flags generated by `cdk init`.

## First time

Bootstrap the account once, then deploy: see
[docs/runbooks/recruiter-chatbot-aws-setup.md](../docs/runbooks/recruiter-chatbot-aws-setup.md).

## Deploying

Always through the deploy script, which validates the profile and builds the bundle the stack
uploads (`mcp-server/dist/lambda/`):

```bash
bash mcp-server/deploy-mcp.sh --profile-dir <path-to-your-profile>
```

## Commands (run in `infra/`)

```bash
npm ci               # install the exact versions from package-lock.json
npm test             # check the stack's rules without AWS (CDK assertions + Vitest)
npm run typecheck    # TypeScript type check
npm run format       # format the TypeScript files with Prettier
npx cdk synth        # write the CloudFormation template to cdk.out/ (needs a built bundle)
npx cdk diff         # what a deploy would change (reads AWS)
npx cdk drift        # settings changed by hand in the console (reads AWS)
npx cdk destroy      # delete the stack
```

`cdk.out/` is gitignored: it holds a copy of the deployment package, profile included.

**Don't change these resources in the console.** Change the code and deploy.
